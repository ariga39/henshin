# Data Model and Persistence

This topic owns logical schemas, keys, constraints, revisions, transaction boundaries, migrations, and backup/export storage. [Backup and archival recovery](backup-and-archive.md) owns operational scope, destinations, bundle publication, retention and restore procedures. [Entry lifecycle](entry-identity.md), [indexing](file-indexing.md), [EH metadata](eh-metadata.md), [reading](external-reading.md), and [consistency](synchronization.md) own behavior. The schema below is the first-release storage contract; executable DDL and adapter selection must implement it rather than inventing alternate ownership.

## Stores and Primitive Types

Use two separate SQLite stores: the authoritative server database on server-local disk, and a desktop database on device-local disk, owned by Electron main while running and by the exclusive stopped-store maintenance tool during maintenance. Clients never open the server database; renderers never open either database. Collection NAS roots contain neither live database nor application temporary outputs. Local databases may back up to a separately configured destination, but live WAL operation requires local storage.

Enable foreign-key enforcement on every connection, WAL journaling, and FULL synchronous durability for authoritative/journal writes. A single application writer serializes short write transactions per store; independent bounded read connections may read snapshots. Synchronous drivers run on a dedicated database worker, never the renderer or server request event loop. No network/filesystem scan, hash, decoder, or reader launch runs inside a write transaction. Busy errors use bounded retries and a clear unavailable result, not infinite blocking. Tune checkpoint cadence and busy deadlines with measured workloads before implementation.

IDs are opaque random UUID text unless supplied by a source. EH gid is a validated canonical decimal string, not a JavaScript floating-point identity. Revisions are nonnegative SQLite integers advanced monotonically within their owner; transport encodes them as decimal strings to avoid JavaScript integer truncation. UTC instants use integer milliseconds with a validated supported range. Store original Unicode strings without search/path normalization. JSON fields contain validated, size-bounded structured data and a schema/profile version; JSON never replaces searchable relations or key constraints.

Authority epoch is ephemeral process-start state, not an entry key or a counter restored from backup. Persist instance ID, schema version, and one stable library ID. A database schema newer than the binary supports fails startup before serving requests. Immutable IDs and retired mapping/generation identifiers are never reused.

The prototype server uses the process-lifetime local directory ownership adapter described in [deployment](architecture.md#managed-local-service). Acquisition precedes the database worker and release follows its cleanup; [executed evidence](../validation/g1-g2-runtime-persistence-prototype.md#server-ownership-precursor-executed) records the measured scope and remaining limits.

## Authoritative Server Schema

All tables live within one server instance. The instance ID is stored once in `server_state`; wire envelopes supply it. References use foreign keys, and UUIDs are unique within their table across the instance. The first release creates exactly one visible `libraries` row and exposes no library creation/deletion API.

| Table / key | Stored responsibility and constraints |
| --- | --- |
| `server_state` (singleton) | Instance ID, schema version, optional independent owner-token verifier, installation/configuration identifiers, active alias-dataset/profile pointer, optional active EH credential-version reference (absent means unconfigured); credentials are protected separately as deployment specifies |
| `libraries` (`library_id`) | Display name, library change revision; one initial row, stable across restore/migration |
| `roots` (`root_id`) | Library FK, label, scan-enabled flag, policy revision, exclusion policy; retain disabled roots; root/library pair is unique for composite references |
| `server_mappings` (`root_id`) | Effective Absent/Active/Suspended configuration, mapping revision and non-reused generation, native prefix/canonical evidence/comparison profile; separate draft fields do not replace the effective mapping |
| `entries` (`entry_id`) | Library FK, immutable date added, identity state, decision revision, location revision, content version, accepted observation FK, separate server availability/time, last-known logical location and normalized basename; state constrained to accepted/pending/detached |
| `current_claims` (`entry_id`) | Root/library FKs, original relative path and comparison key; unique `(root_id, comparison_key)`; entry and root must have the same library; detached entries have no row |
| `lightweight_observations` (`lightweight_id`) | Root/path and generation context, comparison profile/time, archive stat hints or direct supported-page original names plus per-page size/mtime; durable before/after/quiet-interval evidence, distinct from acceptance manifests; accepted/candidate observations reference their relevant baseline/check records |
| `observations` (`observation_id`) | Entry or staged candidate owner, format, size/mtime hints, complete supported-page manifest, manifest/analysis profile, optional complete fingerprint/profile, captured mapping/generation/evidence tokens and lightweight-observation references, observation time; distinguish accepted observation from candidate analysis |
| `replacement_candidates` (`entry_id`) | One current candidate per occupied claim, candidate version, current observation/error; prior accepted observation remains referenced by entry |
| `scan_generations` (`generation_id`) | Root/mapping/policy versions, durable Hold-new-discoveries mode, lifecycle state, per-scope completion/error evidence; retirement is irreversible |
| `staged_discoveries` (`candidate_id`) | Root/path/comparison key, candidate version, analysis reference, latest generation, persisted review hold/revision and its captured evidence; unique current staged target per root/key; no accepted entry ID until allocation |
| `galleries` (`gallery_id`) | Unique `(source, gid)` with common EH source across domains; locator/token, preferred domain, credential/request generation, snapshot revision/status, last success/error metadata |
| `gallery_snapshots` (`gallery_id`) | Current validated source fields, raw bounded response/profile, retrieval time, normalized title copies; replace a successful snapshot atomically, retaining it on refresh failure |
| `bindings` (`entry_id`) | At most one gallery FK, binding origin/time; edits share entry decision revision |
| `entry_overrides` (`entry_id`) | `title_present` boolean plus nullable title value, notes, rebind-review indicator, normalized local title/profile; CHECK ensures absent title has null value and present title has a string including empty; entry decision revision protects edits |
| `tags` (`tag_id`) | Unique exact `(namespace, original_text)`; no Unicode/lowercase normalization of identity; `local` reserved for local-only tags |
| `gallery_tags` (`gallery_id`, `tag_id`) | Source membership set with composite primary key |
| `entry_tag_overrides` (`entry_id`, `tag_id`) | One action, add or suppress, per canonical EH tag; local-namespace tags permit add only, and removal deletes that row without creating a suppression; reset deletes row; effective tags follow `(source minus suppressions) union additions` |
| `tag_aliases` (`dataset_version`, `tag_id`, `language`, `alias`) | Versioned translated labels with normalized searchable copy; aliases never define tag identity |
| `device_labels` (`device_id`) | Unique instance-local provenance ID, label, edit revision; no authentication role; unknown historical IDs can display raw ID until registered |
| `open_events` (`event_id`) | Entry FK, immutable device ID, observed location/content revisions, occurrence time, receipt time; unique across entries/devices; device registry not a required FK for admission |
| `entry_statistics` (`entry_id`) | Rebuildable accepted-event count and maximum occurrence time; no local pending events |
| `operation_results` (`epoch`, `operation_id`) | Command type, canonical validated nonsecret payload and protected secret-version references where needed, result, and `created_at_ms`; the seven-day result expiry is derived from that stored creation time, duplicates compare complete logical payload through the credential adapter, not just a hash/redacted marker, and effects/result commit together |
| `tasks` (`task_id`) | Type/target, status, attempt/checkpoint, generation/owner fences, next attempt time, bounded error/progress; durable scheduling/coalescing keys |
| `backup_destinations` (`destination_id`) | Registered native output boundary and evidence, redacted display label, schedule/retention policy, settings revision and reconciliation/enablement state; last destination-pressure observation (time, unknown/ok/low/unavailable, nullable available bytes, bounded diagnostic); snapshot-backed application configuration, registration restricted to local administrator maintenance |
| `maintenance_artifacts` (`artifact_id`) | Store namespace/kind, task/operation and destination IDs, generated relative artifact name, publication order, retention class, snapshot metadata, payload/manifest digests, included/excluded data classes and publication/verification state; durable reservation before output, no source paths or implicit deletion authority |
| `maintenance_drills` (`drill_id`) | Originating store namespace, artifact ID/manifest digest, start/completion times, measured duration, Running/Pass/Fail/Interrupted state and bounded check/diagnostic results; recorded in the original store under its stopped-store lock; retain latest attempt and latest pass per artifact, never infer evidence for another digest |
| `maintenance_status` (singleton) | Latest timestamped local-staging pressure observation (unknown/ok/low/unavailable, nullable available bytes, bounded diagnostic); measured against task capacity budget, not a reservation |
| `thumbnail_refs` (versioned key) | Entry/candidate owner, content/candidate version, page identity, rendering profile, size, cached filename if present; files remain evictable and regenerable |

Lightweight records preserve the accepted comparison baseline and current candidate stability evidence across restart; incomplete records cannot establish stability. Retain referenced evidence and expire only unreferenced superseded observations. The complete acceptance manifest remains a separately versioned artifact, not something enumeration must regenerate merely to compare page stats.

Store a complete page manifest as a versioned bounded record or child page rows, selected after measuring representative directory/archive counts; either representation must preserve original member identity/order and atomic completeness. This physical layout choice does not change observation ownership or permit partial manifests to be accepted. Raw source responses and diagnostics are not indefinite request logs; retain the latest useful state with bounded error history, excluding secrets.

Last-known location is a non-reserving display/diagnostic copy; current claims alone authorize resolution. Derive the searchable basename from the current claim when present, otherwise the retained last-known spelling, and update its normalized copy transactionally. Galleries/tags/aliases are instance-wide under the one-visible-library default; any future multi-library change must deliberately review sharing/privacy rather than merely exposing another library row.

A current claim retains its reservation even if availability is missing/inaccessible or identity is pending. Keep server availability observations and scan-scope inclusion separately from identity state. Accepted and pending entries each require exactly one current claim; detached entries require none. Observation ownership is exclusive (entry or staged candidate), and accepted/candidate references must agree with that owner. Transfer a staged observation to its newly allocated entry in the allocation transaction; use deferred foreign keys where cyclic entry/observation creation requires them. Application transaction helpers enforce these cross-table cardinalities before commit, while PK/FK/unique/CHECK constraints enforce the expressible local invariants. No public command writes raw table rows.

`comparison_key` comes from the verified native path adapter under the root's actual comparison profile, not `lower(path)` or Unicode search normalization. Preserve original spelling separately. Adapters must demonstrate equivalence/collision behavior, including per-directory semantics, before publishing claims. An exact-only supported mode uses enumerated canonical spelling and rejects unproven aliases as the [path contract](path-mapping.md) requires. A changed mapping/profile must validate existing claims together and reject/suspend ambiguous activation; never rewrite keys incrementally while exposing conflicting current claims.

## Revisions and Conditional Transactions

| Mutation | Atomic writes and required fences |
| --- | --- |
| Root mapping activation/removal/suspension | Match mapping revision/generation, recheck overlap against all active roots, update effective state, invalidate affected scan generations, advance library change revision for changed projections |
| Exclusions or scan enablement | Match root policy revision, update policy, irreversibly retire active generation, retain staged records/holds for fresh validation, advance library change revision |
| Stop scanning a replacement location | Match entry decision/location/candidate revisions and root policy revision; add the exact-path exclusion, retain old claim/pending state, advance relevant decision/policy/library revisions, retire the root generation, and store the operation result; no successful analysis required |
| Detach a confirmed-missing claim | Match entry decision/location revisions and current confirmed-missing state; copy current location to last-known, remove only its claim, set detached, retire any candidate decision, advance decision/location/library revisions, retain metadata/history, and store the operation result under the current epoch |
| Publish scan result | Check current root mapping/policy/generation and candidate/claim versions; successful scoped evidence only; update observation/status and affected library revision |
| Stage/hold a new target | Insert/update candidate version and analysis; pre-scan Hold mode sets hold in that same insert; conditional reserve conflicts if an accepted claim already owns it |
| Release a staged hold | Match candidate version, hold revision, mapping/policy context; clear hold and advance its revision, invalidate the old review decision, then schedule fresh reconciliation; never force allocation from stale evidence |
| Accept new entry or relocate | Recheck fresh evidence and current claims, scan context, hold/decision authorization, and library membership; allocate once or transfer one claim; update versions/accepted observation/statistics initialization, advance library change revision, and store the command operation result under the current epoch in the same transaction |
| Resolve replacement as new edition | Match entry decision/location/candidate versions and fresh stable acceptance evidence; copy the old current location to last-known, detach the old entry and release its claim, advance its decision/location revisions, insert a new unbound entry/claim with empty personal history, retain old records and retire the candidate; advance library change revision and store the operation result under the current epoch in the same transaction |
| Resolve replacement as same edition | Match entry decision/location/candidate versions and fresh stable acceptance evidence; retain records and advance decision revision; advance content version unless exact comparable equality permits retaining it; clear the candidate and invalidate derived references as required by the content version; advance library change revision and store the operation result under the current epoch in the same transaction |
| Binding/override edit | Match entry decision revision, mutate source relation/local values, advance decision/library revisions, update normalized local text; no old-gallery projection may survive the commit |
| Publish EH snapshot | Match gallery request/credential generation and snapshot fence, replace validated snapshot/tags, advance gallery revision and every affected library change revision; never overwrite entry overrides |
| Publish translation aliases | Validate/stage one complete dataset version, atomically switch the active dataset/profile pointer and advance affected library change signals; no tag identity or selected chip changes; incomplete downloads leave the old pointer active |
| Change EH credential or locator | Prepare immutable protected credential version outside the transaction, then conditionally activate its reference/generation and invalidate old refresh authority; a gallery-token change additionally matches gallery revision and required verification evidence; failed preparation keeps old active reference, inactive orphan versions can be cleaned later |
| Accept open event | Validate retained entry, insert unique immutable payload, update statistics and library revision, commit before acknowledgment; duplicate identical payload returns prior receipt without increment |
| Rename device label | Match label revision, update label/revision; refresh history projection signals without rewriting events |

Entry decision revision advances for identity decisions, candidate replacement/clearance, binding and local-override changes. Location revision advances only when the logical claim changes/detaches; content version advances under the identity evidence rule. Availability-only observations do not masquerade as content verification. Mapping revisions and root policy revisions are distinct: scan jobs capture both. Database writes use current authority epoch validation before dispatch/commit; a restored process cannot inherit old in-memory write authority.

For retransmitted commands, look up the operation ID under the accepted current epoch before reevaluating the original revisions: an identical canonical payload returns its stored result and original creation-derived expiry, and a different payload conflicts. Persist the result and all effects atomically; retention and expired or changed-epoch outcomes follow [consistency](synchronization.md#concurrent-commands-and-ambiguous-results). The isolated prototype retains at most 64 result rows per store. Before a new result is admitted, one bounded transaction compacts expired rows and rows from obsolete epochs; it never evicts an unexpired current-epoch result. If the store remains full after that bounded cleanup, the cleanup commits independently and the mutation returns tagged `storage_full503` without changing the note or inserting its result. Repeating the same operation ID can therefore make bounded reclamation progress; it does not turn old-epoch absence into replay authorization.

Use `BEGIN IMMEDIATE` for conditional writes to acquire the writer before reading preconditions; rollback all effects on constraint/conflict/error. File analysis happens beforehand with captured evidence tokens, then the commit rechecks their database ownership. There is still no atomic transaction with the external NAS. Publish notifications only after commit; notifications need no durable outbox because reconnect/periodic reads provide convergence.

For shared-gallery refresh, query effective fields through current bindings and indexed relations rather than materializing every entry's title/tag projection initially. Maintain normalized source/local strings in the same source transaction. This avoids asynchronous stale rebound projections and large fan-out rewrites. Statistics remain synchronous per-entry aggregates. Rebuildable acceleration must preserve [search](search.md) correctness and version gates.

## Desktop Schema and Retention

While the desktop is running, Electron main is its only store writer and coordinates all windows. The stopped-store maintenance entry point may write under the same exclusive lock after main exits. The installation ID is shared across connections; the remaining namespace-sensitive records include instance ID in their keys.

| Local table / key | Responsibility |
| --- | --- |
| `installation` (singleton) | Random device ID, local schema version; preserve across normal upgrades |
| `connections` (`profile_id`) | URL, expected instance ID, credential-store reference, compatibility/connection preferences; no raw secrets in renderer caches |
| `client_mappings` (`instance_id`, `root_id`) | Effective mapping/draft, mapping revision/generation, canonical evidence and profile; preserve tombstone generations on removal |
| `reader_profiles` (`profile_id`) | Locally selected native executable/mode, ordered argument tokens, format/target preferences, profile revision |
| `launch_journal` (`instance_id`, `action_id`) | Entry/context/profile versions, prepared/unresolved/accepted/failed/acknowledged state, immutable event payload when accepted, upload/held diagnostics, acknowledgment metadata |
| `display_cache` (namespace/resource/version key) | Bounded fetched entry/root/collision/manifest/thumbnail display data, epoch/freshness; freely evictable independently of journal |
| `unsent_drafts` (namespace/entry/form key) | User-retained metadata form values, local draft revision, base server revision/epoch; conditional save/discard through main prevents another window overwriting a saved draft; never stores credentials or becomes a mutation queue |
| `command_attempts` (`instance_id`, `operation_id`) | Durable prepared/submitted/unresolved/terminal tracking for side-effecting server commands: operation kind, target IDs, safe intent summary, base revisions/epoch, submission time, result/expiry/task ID; no raw credentials and no automatic restart replay |

Offline desktop maintenance keeps its destination/artifact catalog, drill records and pressure status in the desktop store under the same responsibilities as the server tables above, with local maintenance operation IDs rather than foreign keys to server tasks; it does not enable a desktop background backup scheduler. All restorable nonsecret configuration is persisted in its owning store; bundle configuration is a projection of that snapshot, not another authoritative input.

Record a command attempt before HTTP dispatch and its result afterward; on crash or lost response, preserve it for status/current-state reconciliation. Failure to record prevents submission. Credential-changing attempts store redacted intent/protected references, not secret payloads. Keep unresolved attempts until resolved or explicitly dismissed; dismissal does not cancel a possibly committed command. A dismissed unresolved attempt is hidden from the normal recovery list but remains locally recoverable for seven days; only that explicit dismissal makes it eligible for bounded cleanup after the retention window. Undismissed unresolved attempts are never evicted for capacity. Terminal attempt diagnostics may follow the seven-day retention below.

Main atomically admits only one active Open per instance/entry before asynchronous preparation; this process-lifetime slot is separate from journal retention. Retained unknown diagnostics and accepted events awaiting upload do not lock an entry. A prepared launch intent is durably committed before dispatch. Accepted event state is committed after OS acceptance; the unavoidable gap and unresolved-intent recovery follow reading. Marking acknowledgment/removing from pending is one local transaction. Keep all pending/held events until acknowledgment or explicit user discard; cache cleanup cannot touch them. No journal record can transition back into a launch command after restart.

Proposed initial retention: retain acknowledged/definitely failed action diagnostics for seven days and operation results for seven days within their epoch. Public command responses advertise result expiry; clients stop automatic retries before that boundary. Unresolved launch intents remain until explicit dismissal; their UUIDs are not reused. Never purge an in-flight operation's result. A new server epoch disables automatic command retries independently of retention. Open-event IDs on the server have no TTL while history is retained. The isolated operation-result prototype uses a 64-row cap; status lookup never compacts or otherwise writes.

Before implementation, choose finite journal/cache/response capacities with actionable full-store errors and crash-safe compaction. The required rule is preserve pending history and block new counted launch before exceeding the durable journal budget, not a universal numeric limit absent collection evidence. Back up a desktop profile only with a consistent local snapshot; independent-profile export excludes live journals, credentials, drafts and command attempts and creates a new installation ID under [backup and recovery](backup-and-archive.md). Moving the same installation while it is stopped can preserve its journal, but must not leave two live copies draining it.

## Indexes, Migrations, and Derived Files

Required relational indexes cover current claims by root/key, entries by library/date-added/ID, pending/missing status, bindings by gallery, gallery tags by tag/gallery, overrides by tag/entry/action, open events by entry/occurrence/ID, tasks by status/next-attempt/coalescing target, and staged candidates by root/hold/generation. Title/publication/rating/count sorts use appropriate typed keys and deterministic entry-ID ties. Exact composite index selection and query plans are measured against the correctness fixtures; FTS is not required merely because search exists.

Version each store independently. Migrations run exclusively before serving or dispatching launch actions, under the data-directory lock. Create and validate a pre-migration consistent backup; apply versioned schema/data steps transactionally where SQLite permits. On failure, leave the prior database recoverable and fail startup with recovery instructions, never continue on a half-migrated schema. There is no automatic downgrade. Migration tests must cover the previous supported version and interrupted writes; compatibility versions are [deployment](architecture.md) decisions.

Thumbnails are written to a temporary file in the application cache, then atomically renamed and conditionally referenced after version checks. A crash may leave an orphan file or a missing derived file; cleanup/regeneration handles both without deleting authoritative records. No database transaction pretends to atomically roll back an external file rename. Backup need not include thumbnails; all required selected-page/content/profile metadata remains in the database.

## Backup, Restore, and Export

Use SQLite's backup facility (or an adapter-proven equivalent consistent snapshot), not a copy of a live main database file that ignores WAL. [SQLite WAL documentation](https://www.sqlite.org/wal.html) describes same-host requirements, the single writer, and WAL's persistent state; [Online Backup](https://www.sqlite.org/backup.html) describes consistent snapshot backups. Both were inspected on 2026-10-18; no adapter backup test has run.

[Backup and archival recovery](backup-and-archive.md) owns bundle payloads, verification/publication, server and desktop maintenance, retention and restore ordering. Persistence supplies a consistent snapshot with domain/FK integrity, a durable destination/artifact catalog and transactional policy revisions. Catalog reservation/publication/deletion transitions are serialized with destination policy changes; catalog loss never grants pruning permission. Publication and registration remain separate recoverable steps. Restore/migration/clone/rollback must preserve identity according to consistency, clear copied active credential state, and invalidate derived caches according to the recovery contract before activation. No live-file copy may substitute for a consistent snapshot, and no procedure writes collection sources.

Metadata export is a versioned UTF-8 JSON document or stream with a manifest header, server/library IDs, export time, field-schema version, and per-entry records: entry ID/state, logical root ID/relative path, local format/page count, binding public gallery URL, permitted source titles/tags/category/rating/publication, local overrides, and aggregate open count/last-opened. Include bound, unbound, missing, and detached entries under the user's explicit export scope. Omit native prefixes, credentials, raw EH responses, executable profiles, file bytes, and per-event device history by default. Gallery URLs necessarily contain their gallery locator; state that the export is private before writing it. Notes are personal metadata and included only with an explicit include-notes option.

Generate export from a consistent temporary snapshot so long serialization does not hold the live database read transaction open indefinitely. Mark its snapshot time and selected entry IDs; explicit IDs that no longer exist are reported, not silently replaced by a new query. Export is not a backup, content archive, or re-import contract. Destination selection belongs to the local administrator/client workflow in [contracts](api-and-tasks.md); remote users must not supply arbitrary server filesystem paths.

## Acceptance and Implementation Gates

Verify concurrent claim allocation/case-only rename under actual comparison adapters; stale root/generation/candidate commits including Stop-scanning after another resolution; standalone missing-claim detachment; persisted per-page lightweight comparison after restart; hold-release and alias/credential publication failures; pre-scan holds across restart; replacement transactions interrupted at each write; binding refresh during rebind; identical versus conflicting duplicate events; aggregate rebuild equivalence; local intent/event/ack crash windows; busy/disk-full errors; migration rollback; online backup under writes; interrupted backup publication; and restore with missing post-backup entries/events. Exercise foreign-key and domain invariants after each failure fixture.

Before implementing, pin a compatible SQLite adapter/runtime, executable DDL, transaction helpers, canonical command payload encoding, manifest layout/limits, and measured query plans. These choices must preserve the schemas and atomic rules above. No database tests, integrity checks against a real application database, or runtime performance measurements have yet been executed. [Delivery](delivery-and-validation.md) owns the recorded verification matrix.
